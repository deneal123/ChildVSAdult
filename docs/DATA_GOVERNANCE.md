# Data Governance — датасет, обезличивание, правовая основа, DPIA

Рабочий governance-документ проекта (RU). Сопровождает релиз и подаётся как приложение к статье
(datasheet + DPIA). Цель — снять этико-правовые риски биометрического датасета и не получить
desk-reject. **Не юридическое заключение:** ключевые узлы (биометрия по 152-ФЗ, несовершеннолетние)
требуют этической экспертизы организации и консультации профильного юриста.

> Прецеденты, почему это критично: отзыв MS-Celeb-1M, DukeMTMC, Brainwash (scraping без согласия);
> санкции DPA против Clearview AI за facial scraping публичных фото. «Публичное + официальный API» —
> НЕ оправдание (см. §3).

---

## 1. Назначение и scope

Исследование age-invariant identity matching на «естественно заякоренных» longitudinal-парах из
публичных мультифото-постов VK. Биометрические данные (лица) + возраст. Назначение — **только
research**; controlled / consent-based / human-reviewed применения. Вне scope и запрещено: массовая
идентификация, слежка, деанонимизация, реидентификация, коммерческое использование, обработка данных
несовершеннолетних без правовой основы.

## 2. Datasheet (по Gebru et al., кратко)

- **Мотивация:** дефицит размеченных longitudinal cross-age пар; исследование label-free источника.
- **Состав:** 44 609 постов → 49 606 usable-лиц → 21 847 личностей (после чистки 21 427 групп / 40 586
  лиц / 31 865 позитивов). Атрибуты: кроп лица (112px), возраст из подписи (regex+LLM), apparent
  пол/возраст (genderage), псевдонимный person_id. Источник — 2 публичных сообщества VK, русскоязычный
  контекст. Перекос: 76.7% apparent-female / 23.3% apparent-male; есть несовершеннолетние (страта 0–17).
- **Сбор:** официальный VK API (`wall.get`), только публичные стены. Дата сбора фиксируется per-item.
- **Препроцессинг:** RetinaFace-детекция + 5-точечное ArcFace-выравнивание; фильтры usable; person-
  кластеризация (cos≥0.85); дедуп near-duplicate (cos≥0.97); LLM-валидация целостности групп.
- **Использование:** обучение/оценка cross-age верификации (внутренний протокол) + внешние бенчмарки.
- **Распространение:** см. §4 — сырые лица/посты НЕ распространяются.
- **Сопровождение:** контакт для takedown (§7); поля retention/deletion per-item.

## 3. Правовая основа и пробелы (честный анализ)

| Норма | Что требует | Наш статус |
| --- | --- | --- |
| 152-ФЗ ст. 11 (биометрия) | **письменное согласие** на биометрию для установления личности | ❌ нет |
| 152-ФЗ + 519-ФЗ (2020) | «данные, разрешённые для **распространения**» → отдельное согласие | ❌ нет (публикация ≠ согласие) |
| 152-ФЗ / 242-ФЗ | локализация ПД граждан РФ в РФ | ⚠️ хранение локально, учесть |
| GDPR ст. 9 (спецкатегория) | оговорка ст. 9 для биометрии; «manifestly made public» — узко | ⚠️ опора на 9(2)(j) research |
| GDPR ст. 6 | legal basis | research / legitimate interest (ст. 6(1)(f)) |
| GDPR ст. 89 | safeguards для научного исследования | ✅ минимизация/псевдонимизация (§4) |
| GDPR ст. 35 | DPIA для биометрии в масштабе | ✅ см. §5 |
| GDPR ст. 8 / 152-ФЗ | данные несовершеннолетних — строжайше | ⚠️ см. §6 (изъятие из релиза) |

**Вывод:** официальный API и публичность поста **не** дают права на биометрическую обработку. Явного/
письменного согласия нет. Опора — научно-исследовательский режим + компенсирующие меры (§4–§7). Пробел
фиксируется прозрачно; до развёртывания — этическая экспертиза + юрист.

## 4. Обезличивание и политика релиза (de-identification)

**Принцип: НЕ публикуем сырые лица и сырые посты.** Публичный релиз = только:

- код, конфиги, веса обученной модели;
- **производные эмбеддинги** (не изображения);
- псевдонимизированный бенчмарк-протокол (пары по псевдо-id);
- агрегаты/таблицы статистики.

**Меры обезличивания (реализовано: `scripts/anonymize_release.py` + safety-scan; проверено: 0 сырых
VK-id в релизе, 8 201 minor-лицо исключено):**

1. **Хеширование идентификаторов:** owner/photo/post ID → `HMAC-SHA256(id, secret_salt)`; соль не
   публикуется → обратная связь с VK-профилем невозможна.
2. **Удаление PII:** подписи/комментарии (имена, контакты) исключаются из релиза; хранится только
   возраст-бакет + псевдо-person_id.
3. **Без сырых кропов:** кропы лиц только локально, под retention-политикой; в релиз не идут.
4. **Фигуры статьи:** без идентифицируемых лиц (только агрегатные графики; примеры — из публичных
   FG-NET/LFW или синтетика, не из VK).
5. **Controlled access:** неагрегатные производные — квалифицированным исследователям по **Data Use
   Agreement** (research-only, запрет реидентификации/коммерции/слежки).
6. **Минимизация:** не храним соцграф, лайки-с-именами, гео; только кроп(локально)+возраст+псевдо-id.

## 5. DPIA (Data Protection Impact Assessment) — риски и меры

| Риск | Серьёзность | Мера снижения |
| --- | --- | --- |
| Реидентификация субъекта по релизу | высокая | не релизить сырые лица; хеш-id; controlled access (§4) |
| Function creep (слежка/массовая ид.) | высокая | research-only лицензия; human-in-the-loop; запреты (§1) |
| Данные несовершеннолетних | высокая | изъятие страты 0–17 из релиза; только агрегат (§6) |
| Утечка локального сырого набора | средняя | локальное хранение, доступ ограничен, retention/deletion |
| Демографический bias/вред | средняя | аудит справедливости (в статье); прозрачность перекоса |
| Инверсия эмбеддингов → лицо | средняя | оценить риск инверсии; при необходимости — не релизить эмбеддинги, только метрики |

## 6. Несовершеннолетние

Режим child↔adult включает изображения несовершеннолетних — строжайшая защита (152-ФЗ; GDPR ст. 8).
**Меры:** элементы детского возраста помечаются (`apparent_age < 18`); **исключаются из любого релиза**
при отсутствии явных правовых рамок и проверяемого согласия законного представителя; используются
только для агрегатного, не-распространяемого анализа. В статье — отдельный параграф (§8.4 черновика).

## 7. Права субъектов / takedown

- Публичный контакт для запросов на удаление (указать e-mail/форму при релизе).
- Процедура **удаления по запросу**: пометка `deletion_status=deleted` → элемент исключается из всех
  производных артефактов при следующей пересборке; хеш-id позволяет найти элемент без раскрытия личности.
- Где права неясны — элемент удерживается (`review_status`).
